<objective>
Unify SpotOn auth into ONE step (GH #147 endgame): replace the ncspot bundled Client ID with Spotify's Keymaster client_id as the PKCE default, redirect to a dynamic loopback URI pointing at LMS's own pkce/callback endpoint, and — because a Keymaster-minted full-scope token has the provenance Login5 accepts (spike-proven 2026-08-13) — automatically derive playback credentials via the existing deriveCredentialsFromToken (65-03) when the token exchange completes. Result: Authorize once → Browse + Playback + Connect all work.

This amends CONTEXT decision D-02 ("ZeroConf primary, browser fallback secondary") per explicit user direction after today's spike: Keymaster-PKCE becomes the primary path; ZeroConf pairing (65-02) and the playerauth browser fallback (65-03) stay untouched as fallbacks. D-03 (no Rust changes) and D-05 (crash-loop fix unconditional) are unaffected. D-04's ban on wrong-provenance auto-derivation stays enforced: the auto-derive fires only when the exchanged token is Keymaster-minted, only once, only at user-initiated auth completion — _handleCredentialCrash and all crash paths remain fully defused (65-01).

Purpose: Collapse the 3-step onboarding (Developer App + PKCE + pairing) to a single Authorize click; existing accounts flagged legacy_token_derived (65-03 migration) recover with one re-auth.
Output: Keymaster-default PKCE flow with loopback-to-LMS redirect, auto-derivation tail, Keymaster refresh fallback, collapsed Custom App UI, strings in 11 languages.
</objective>
