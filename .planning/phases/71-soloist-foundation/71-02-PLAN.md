noun: "helper" / Daemon-Instanz (`$helperInstances{$clientId}`, `startHelper()`, `stopHelper()`)
decision: no-change
rationale: Diese Phase führt ein ZWEITES Audio-Backend (Soloist neben librespot) ein — ein Singular→Plural-Übergang beim Backend. Das Identitätsmodell des DaemonManagers benennt jedoch KEIN Backend, sondern eine Daemon-Instanz pro Player (keyed by clientId). Ein Backend ist lediglich die Wahl, WELCHES Binary eine Instanz spawnt — ein Verzweigungspunkt innerhalb von startHelper(), keine neue Identität. Der Crash-Backoff/%crashRestarts-State ist bereits backend-agnostisch (keyed by mac). Daher bleibt die "helper/instance"-Benennung korrekt; kein promote/add-alongside nötig. Sollte Phase 74 (Per-Player-Backend) pro Instanz unterschiedliche Backends erlauben, bleibt das Instanz-Modell weiterhin tragfähig (Backend wird dann Instanz-Attribut, nicht Identität).
</assumption_delta_decision>
