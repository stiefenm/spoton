**Ring buffer + conversion (in `pa_stream_write`):**
- Static bounded ring of `RING_CAPACITY = 352800 * 2` bytes (~4 s of S16LE 44100/stereo; pacing depth per RESEARCH ~1-2 s of decode-ahead once half-full steady-state is reached), guarded by a dedicated mutex + two condvars (space_avail, data_avail).
- Convert incoming samples to S16LE based on the stream's `sample_spec.format` captured at `pa_stream_new`: FLOAT32LE → `s16 = (int16_t)lrintf(clamp(f, -1.0f, 1.0f) * 32767.0f)` (link with -lm for lrintf); S32LE → arithmetic shift right 16; S16LE → memcpy. Phase-72 UAT established soloist emits float32 — the other two branches are cheap defensive completeness, not speculation.
- Full ring + HTTP client connected → block the producer with `pthread_cond_wait` on space_avail (this IS the realtime pacing, RESEARCH "Don't Hand-Roll"); full ring + NO client → drop oldest bytes (advance read pointer) so soloist never blocks while LMS isn't reading (Connect active, player paused).
- `pa_stream_writable_size`: in HTTP mode return free ring space (bounded pacing signal, fixes the constant-65536 decode-ahead of Pitfall 5); non-HTTP mode keeps 65536.
- `_stream_refresh_timing`: in HTTP mode report `read_index = bytes_written - ring_fill` (position soloist reports tracks what has actually left toward the player, limiting position_sync drift); non-HTTP mode unchanged.

**HTTP server thread (started from the constructor when HTTP mode is on):**
- `socket(AF_INET, SOCK_STREAM)`, SO_REUSEADDR, bind `INADDR_ANY:0`, `getsockname` for the port, write the decimal port + newline to the file named by `SPOTON_SOLOIST_HTTP_PORT_FILE` (open O_WRONLY|O_CREAT|O_TRUNC 0600, write, close). Binding wildcard is deliberate: LMS players stream `/stream` directly from the LAN — identical exposure to the existing librespot `/stream` (RESEARCH Security V4; the WS API in contrast stays 127.0.0.1, enforced Perl-side in Task 2). Document this in a comment.
- Single server thread multiplexing with `poll()` over {listen_fd, client_fd}: on a new accept while a client is connected, close the old client fd and switch to the new one (takeover semantics, blueprint unified.rs relay generation M15). Read and discard the request head up to the blank line (bounded buffer, 2 s timeout); any GET is answered — path checking beyond `/stream` prefix is unnecessary on this single-purpose port but log-free reject of non-GET is fine.
- Response header exactly: `HTTP/1.0 200 OK\r\nContent-Type: audio/L16;rate=44100;channels=2\r\nConnection: close\r\n\r\n` (librespot parity — ProtocolHandler already suppresses Range/Enhanced-HTTP for `/stream` URLs, and getFormatForURL maps `:port/stream` to 'pcm'). No Content-Length (endless stream).
- Body loop: pop from ring (cond_wait on data_avail when empty), non-blocking write to client with poll-based writability wait; client write error → close fd, signal space_avail (unblock producer), return to accept state. SIGPIPE is already ignored by the existing constructor.
