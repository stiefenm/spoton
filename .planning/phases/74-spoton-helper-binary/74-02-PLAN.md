  </read_first>
  <behavior>
    - patch on a fixture reporting the locked version, with all patterns present at their expected counts → applies Lifetime replacement + 5 FLAC24 gates, leaves Gate 4 untouched, atomic-renames the staged file over the original, exits 0
    - patch on a fixture whose embedded version != 1.3.7.489 → aborts with JSON error, target byte-identical (no write)
    - patch on a fixture where a pattern's occurrence count != expected → aborts with JSON error before any write, target byte-identical
    - patch with the empty (public stub) pattern table → reports `unsupported`, exits cleanly, no write (per Task 1 decision default)
    - after a successful patch, scan_status(&patched_bytes) returns lifetime:true, flac24_gates == [true,true,true,false,true,true] (Gate 4 index skipped), patched:true
  </behavior>
  <action>
Define the pattern-table data model in patterns.rs: a `PatchSite { name: &str, search: &[u8], replace: &[u8], expect_count: usize, skip: bool }` and a per-arch table selector `sites_for(arch: &str) -> &[PatchSite]` keyed by the "x86_64-linux"/"aarch64-linux"/"armhf-linux" arch strings from arch.rs. Per the Task 1 decision, the public table is EMPTY (an empty slice per arch) with a clearly marked injection point comment; the real per-arch entries (Lifetime ASCII-timestamp site, and six FLAC24 gate sites with the fourth carrying `skip: true`) are injected from the private validated source at release build time. Do NOT write the concrete byte values into this file in the public checkout.

encoding.rs: per-arch helpers documenting that FLAC24 gates are immediate-compare instructions whose byte encoding differs across x86_64 (cmp imm8), aarch64 (cmp wN,#imm) and armhf (cmp rN,#imm) — this module holds the arch-dispatch scaffolding the injected table plugs into, not the concrete immediates.

mod.rs — replace the stubs with the real engine. `run(version, binary)`:
1. Version gate: read the target bytes, confirm the embedded soloist version marker equals `version` (the caller passes SOLOIST_VERSION 1.3.7.489); if not, return a JSON error and exit non-zero, writing nothing.
2. Resolve arch via arch::read_arch; select `sites_for(arch)`. If the table is empty, print a JSON object with `status`:"unsupported" and exit 0 without writing.
3. Exact-occurrence assertion: for every non-skip site, count occurrences of `search` in the file; if any count != `expect_count`, abort with a JSON error naming the failed site — no partial writes.
4. Apply: build a patched byte buffer, replacing each non-skip site's `search` with `replace`. Skip sites (Gate 4) are asserted-present-but-not-replaced so the count discipline still validates the binary shape.
5. Stage + self-verify + atomic rename: write the patched buffer to a temp file in the SAME directory as the target, run the internal scan_status against the staged bytes to confirm the expected post-patch state, and only then `std::fs::rename` over the original. On any verify failure, delete the staging file and abort.

Rewrite `scan_status(bytes)`: for the resolved arch, report `lifetime` true when the Lifetime site's `replace` bytes are present, each `flac24_gates[i]` true when gate i's `replace` bytes are present (a skip gate reports based on its own presence rule), and `patched` true when the Lifetime patch and all non-skip gates are applied. With the empty public table, everything reports false (matching Plan 01 behavior).

Add `#[cfg(test)]` unit tests that inject a small TEST-ONLY pattern table (synthetic search/replace markers, unrelated to the real patterns) and drive the five behaviors above against fixtures produced by tests/fixture.rs helpers.

After a successful atomic rename in `run`, compute the SHA256 of the final patched file and write it to a sidecar file `<binary>.sha256` in the same directory (single hex line). This is the integrity baseline (D-07): `check --expect-sha` in Plan 01 already compares a provided hash; document that Soloist.pm (Plan 04) reads this sidecar and passes it to `check`. On a re-run of `patch` against an already-patched binary, the version gate still passes but the exact-count assertion for the Lifetime/gate `search` bytes will find zero occurrences (they were already replaced) — treat this as the idempotent "already patched" case: detect it by first calling scan_status and, when `patched` is already true, emit a JSON object with `status":"already_patched"` and exit 0 without writing. Add a `#[cfg(test)]` test for the already-patched idempotency path using the test-injected table.
