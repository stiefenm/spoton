    - `protobuf --schema collection-v2 --mode decode` with a valid PageResponse on stdin → emits a JSON object with the decoded fields (items, added_at, is_removed) on stdout, exit 0
    - `--schema recently-played --mode decode` with a valid RecentlyPlayed (backend) message on stdin → emits JSON with the contexts (uri, lastPlayedTime) on stdout, exit 0
    - `--schema rootlist --mode decode` with a valid rootlist Response on stdin → emits JSON with the items/playlists (including uri/row_id) on stdout, exit 0

    - `--mode encode` for a response-only schema (recently-played, rootlist — no request message exists in the upstream schema) → single-line JSON error naming the schema decode-only, non-zero exit
    - malformed/truncated protobuf on stdin → single-line JSON error on stdout, non-zero exit, no panic
    - stdin larger than a sane cap (e.g. a few MB) → JSON error, non-zero exit (reject oversized input)
    - an unknown `--schema` value → JSON error listing the supported schemas (collection-v2, recently-played, rootlist)
  </behavior>
  <action>
Implement protobuf_cmd::run(schema, mode). Read all of stdin into a bounded buffer (enforce a maximum byte cap; if exceeded, return a JSON error and exit non-zero). Match `schema` against the three supported values — "collection-v2", "recently-played", "rootlist" (any other value → JSON error listing all three). Match `mode`:
- "decode": parse the stdin bytes into the generated message for the selected schema using the protobuf crate's parse API (bounded, safe — no `unsafe`, no manual pointer math), then serialize the message to JSON via serde_json and write to stdout. Decode targets: collection-v2 → PageResponse; recently-played → RecentlyPlayed (backend wrapper); rootlist → Response.
- "encode": supported only where the upstream schema defines a request message. collection-v2 → parse stdin as JSON into a PageRequest, encode via the generated type's `write_to_bytes`, write raw bytes to stdout. For recently-played and rootlist (response-only schemas with no request message), return a single-line JSON error stating the schema is decode-only and exit non-zero — this is a schema property, not a deferral.
On any parse failure (protobuf or JSON), print a single-line JSON error object `{"error": "<message>"}` to stdout and exit non-zero — never unwrap/panic on untrusted input.

Add `#[cfg(test)]` tests: for EACH schema a decode round-trip (construct the target message in Rust, serialize to protobuf bytes, feed through decode, assert the JSON contains the expected fields — collection-v2 item added_at/is_removed, recently-played context uri, rootlist item uri/row_id); a collection-v2 encode round-trip (JSON PageRequest → protobuf bytes → parse back → assert equality); an encode-on-response-only test asserting a JSON decode-only error for recently-played; and a malformed-input test asserting a JSON error and non-zero exit with no panic.
  </action>
