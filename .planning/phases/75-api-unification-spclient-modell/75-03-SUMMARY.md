# Phase 75 Plan 03: Remove protobuf subcommand from spoton-helper (D-02) Summary

**Deleted the Rust protobuf codegen pipeline and its two crates from spoton-helper, leaving a leaner patch+check-only binary while the vendored .proto schemas stay as documentation for the new Perl-side ProtobufLite decoder**

## Performance

- **Duration:** ~10 min
- **Tasks:** 2
- **Files modified:** 6 (1 created, 3 modified, 2 deleted)

## Accomplishments

- `spoton-helper/src/protobuf_cmd.rs` (the ~505 LOC protobuf subcommand implementation) and `spoton-helper/build.rs` (its sole job was `protobuf_codegen::Codegen` invocation over 12 proto inputs) are both deleted.
- `main.rs`: `Cmd` enum reduced to `Patch` and `Check`; `mod protobuf_cmd;` removed; crate doc comment rewritten to describe the helper as patcher + integrity checker only, with a note pointing to `Plugins::SpotOn::API::ProtobufLite` as the runtime decoder.
- `Cargo.toml`: `protobuf = "3.7"` dependency line and the entire `[build-dependencies]` section (`protobuf-codegen = "3.7"`) removed; package description changed from "binary patcher, integrity check, schema converter" to "binary patcher and integrity checker".
- `Cargo.lock` regenerated via `cargo build` — shrank from carrying the full protobuf/protobuf-codegen transitive dependency tree to just the remaining 4 direct + their transitives (360 lines → 7 lines net diff).
- `cargo build`, `cargo test` (10 tests: 8 + 2), and `cargo run -- --help` (lists exactly `patch` and `check`) all verified green after the deletion; `cargo tree | grep protobuf` returns no match.
- New `spoton-helper/proto/README.md`: states DOCUMENTATION ONLY status per D-02, names `Plugins::SpotOn::API::ProtobufLite` (D-01) as the runtime decoder and `t/34_protobuf_lite.t` as the golden-vector proof of continued Rust-wire-format parity, names the Spotify 1.2.52.442 extraction source (confirmed via the `// Extracted from:` comment header already present in `collection2v2.proto`), and calls out `collection2v2.proto` specifically as the schema for collection/v2 paging field numbers.
- CI re-verified unaffected: grepped `.github/workflows/build-librespot.yml`'s `build-spoton-helper` job — no protobuf-specific step exists; it runs `cross build --release --target ...` unconditionally, which now simply compiles fewer crates. No workflow change was needed, matching the plan's expected result.
- Plan-scoped re-verification (not the full suite, per the plan's explicit wave-2 race-avoidance instruction since 75-02 was concurrently writing `t/36_spclient.t`): `prove -l t/26_soloist_check.t t/33_soloist_patch.t` — 41 tests, all pass. `cargo test` in `spoton-helper/` — 10 tests, all pass.
- All 12 vendored `.proto` files remain untouched (10 top-level + 2 under `metadata/`), confirmed by directory listing before and after.
