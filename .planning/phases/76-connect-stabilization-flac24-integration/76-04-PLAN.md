<objective>
FLAC24 expansion from the 76-01 tracer: the Soloist format resolver (D-06) with sync-group aggregation, ProtocolHandler consumption (direct-vs-transcode gating per resolved format), and a dedicated MP3 path so every D-07 dropdown value actually does what it says.

Purpose: 76-01 proved the S32→FLAC24 chain; this plan adds the decision layer. Per RESEARCH Open Question 2 / Pitfall 3 (confirmed by the planner): a NEW `resolveSoloistFormat()` sits NEXT TO the existing boolean `resolvePassthroughForClient()` — the boolean contract has 2 librespot consumers (Daemon.pm:128 --passthrough, DaemonManager.pm:980) and must not change.

Design fact established during planning (implement accordingly): `$SAMPLESIZE$` substitutes from `$track->samplesize || 16` (TranscodingHelper.pm:449), so the shared `soc flc` rule from 76-01 is already safe for both backends. Explicit MP3 needs its own content type because TranscodingHelper picks the output format by iterating the PLAYER's format-preference order (TranscodingHelper.pm:352-386) — under `soc`, flc always beats mp3 on flc-capable players, so a `soc mp3` rule could never win there. A single-rule `smp` type is the same forcing idiom SpotOn already uses with `son` (ogg-only).

Output: resolveSoloistFormat + tests, canDirectStream/formatOverride wiring, smp type + rule.
</objective>
