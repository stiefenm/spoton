<objective>
Wave-1 C plan: apply CR-1 (the `g_ring_underrun_fired` atomic fix, per D-01's Wave-0 pre-cleanup lock) and land the phase's headline tracer — the seek-armed flush mechanism (`POST /seek-arm` + conditional `pa_stream_flush()` + drain-loop write gate) that fixes 78-UAT test 10 ("Browse seek closes the HTTP client and skips to the next track").

Task ordering honors D-01 (pre-cleanup lands first) — CR-1 is deliberately Task 1 because it establishes the `stdatomic.h` / `atomic_int` pattern the tracer's new flag reuses (PATTERNS: "use `atomic_int`, not `volatile int`, since CR-1 in the same Wave 0 establishes `atomic_int` as the correct primitive"). Task 2 is the production-quality tracer slice: one path (arm → flush → client survives → only post-flush bytes served) wired end-to-end through the real HTTP thread and real `pa_stream_flush`, proven by a byte-content host test before any expansion work in Wave 2.

Design note (resolves RESEARCH Open Question 1 up front): `g_seek_flush_armed` is a **counter**, not a one-shot bool — each `POST /seek-arm` increments (saturating at 8), each `pa_stream_flush()` decrements when > 0. This makes rapid double-seek (two arms before the first flush lands) safe by construction; Plan 77-05 adds the characterization test.

Design note (arm-counter LIFECYCLE, added per 77-REVIEWS.md HIGH finding): the counter also has a recovery path — the `POST /boundary` handler resets it to 0. Without this, an arm whose flush never arrives (daemon ignores the seek, WS drops between arm and command, play-from-stopped never flushes — RESEARCH A2's unverified corner) would leak forever: the drain gate would withhold all audio, and since boundary EOF is only reached by popping to the watermark, even a `stopped` → `POST /boundary` could never close the client — strictly worse than the seek-skip bug being fixed. A boundary is Perl's authoritative transition signal, so any arm still pending there is stale; the reset self-heals every leak at the next track/session transition. Task 2 lands both the mechanism and the host test that proves it.

Design note (resolves RESEARCH Open Question 2): `getSeekData`'s Browse branch stays unchanged (`{timeOffset=>N}`) — D-02's locked wording ("ProtocolHandler passes start=N") requires the LMS-native seek-restart to remain in place, so the C side MUST handle a fresh client taking over mid-armed-window. That is exactly why the drain-loop write gate (Pattern 1 step 4 / Pitfall 3) is part of this tracer, not an optional hardening.

Purpose: prove the phase's riskiest architectural change (RESEARCH Assumption A2) on the first commit, with the CR-1 foundation in place.
Output: hardened fake-libpulse.c + rebuilt libpulse.so.0 + host-test suite at 12 `ok:` lines.
