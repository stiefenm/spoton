<objective>
Wave-2 Perl plan: relocate the Browse seek dispatch out of Connect.pm's debounced, LMS-`time`-event-driven path into ProtocolHandler.pm's synchronous `getNextTrack` branches, arming the C layer (Plan 77-01's `POST /seek-arm`) before every daemon flush we cause deliberately — seek (D-02) and URI-mismatch play (D-05), the same mechanism used twice per CONTEXT `<specifics>`.

This is the Perl half of the fix for 78-UAT test 10 ("Seek hat kurz geklungen als ob es funktioniert, dann zum Skippen geführt"). The C half (armed flush does not disconnect) landed in 77-01; this plan makes the arm arrive deterministically before the flush by sending the WS command only from within the arm-POST's completion callback — removing the independent-scheduling race entirely instead of narrowing the window (Pitfall 1).

Scope exclusion (deliberate, not dropped): 78-UAT tests 11/15 (Connect transfer resume carrying position `0.000` as trackId) are a SoloistWS.pm/Connect.pm resume-PARAMETER bug with its own root-cause note in 78-UAT.md — it is outside every Phase 77 decision (D-01..D-09 cover bounded-audio hardening, not Connect resume parameters) and stays with Phase 78 gap closure (`/gsd-plan-phase 78 --gaps`). Recorded here so the omission is visible.

RESEARCH assumption A3 (does LMS call getNextTrack again on a seek-restart?) is validated at Plan 77-06's live-UAT checkpoint; documented fallback if it fails UAT: move the arm+seek dispatch into `canDirectStreamSong` (which provably runs on seek-restart — it already appends `start=N` at line 209).

Purpose: deterministic arm-then-command ordering at the single call site LMS's own seek-restart flows through.
